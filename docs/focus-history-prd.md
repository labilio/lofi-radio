**版本**: 1.0
**日期**: 2026-05-24
**作者**: Sarah (Product Owner)
**质量评分**: 92/100

---

## 概要

当前 Lofi Radio 有「今日专注时长」功能，但数据仅保留当天，隔夜即丢弃。用户无法回顾过去的专注情况，也无法了解自己的工作趋势。

本需求引入**专注历史记录**功能：每日专注时长自动存档（保留 90 天），用户通过托盘右键菜单打开历史窗口，以柱状图形式查看过去一周或一个月的每日专注数据。窗口保持打开时，「今天」的数据实时更新。

---

## 问题陈述

**现状**: FocusTimeManager 使用单个 `localStorage` key 存储 `{focusTime, lastDate}`。跨天时 `checkDateReset()` 将前一天数据直接丢弃，focusTime 归零。用户无法看到任何历史记录。

**方案**: 每日结束时自动归档当日专注时长到历史存储。新增独立历史窗口，以 CSS 柱状图展示按日统计的专注数据，支持「周视图」和「月视图」切换。

**业务价值**: 用户能看见自己的专注趋势，增强产品粘性。数据纯本地，隐私安全。

## 成功指标

| 指标 | 目标 | 衡量方式 |
|------|------|----------|
| 历史数据归档 | 跨天后昨日数据不丢失，正确归档 | 手动测试：使用一天后检查 localStorage |
| 历史窗口打开速度 | < 500ms | 目测 |
| 实时更新 | 窗口保持打开时，今日柱状图随播放递增 | 手动测试：开窗口播放 2 分钟，确认数字变化 |
| 数据保留 | 最多保留 90 天，超期自动清理 | 修改本地日期模拟 91 天前数据 |

## 用户画像

**主要用户**: 使用 Lofi Radio 作为工作背景音的开发者/学生/自由职业者
- **目标**: 了解自己每天专注了多久，看看有没有进步
- **痛点**: 今天能看到专注时间，但昨天多少？上周平均多少？完全不知道
- **技术水平**: 普通用户，不需要复杂的数据分析功能

## 用户故事

### Story 1: 查看历史专注数据

**作为** Lofi Radio 用户
**我想要** 在托盘菜单里打开一个历史窗口，看到过去一周每天的专注时长
**以便** 了解自己的工作趋势，而不是只看到今天的数据

**验收标准:**
- [ ] 托盘右键菜单新增「专注历史」菜单项
- [ ] 点击后打开独立历史窗口（可关闭、可拖动）
- [ ] 默认展示过去 7 天的柱状图，每根柱子代表一天
- [ ] Y 轴显示分钟数，X 轴显示日期（如 5/18 ~ 5/24）
- [ ] 今天的数据使用高亮颜色（区别于过去日期）

### Story 2: 切换周/月视图

**作为** Lofi Radio 用户
**我想要** 在历史窗口里切换查看「过去一周」和「过去一个月」
**以便** 从不同时间尺度了解专注趋势

**验收标准:**
- [ ] 窗口内有「周」/「月」切换按钮（或 tab）
- [ ] 周视图显示最近 7 天
- [ ] 月视图显示最近 30 天
- [ ] 切换时柱状图平滑更新（不需要动画，但不要闪烁）

### Story 3: 实时更新今日数据

**作为** Lofi Radio 用户
**我想要** 历史窗口保持打开时，看到今天的柱子随着我继续听电台而慢慢增长
**以便** 不用关闭重开窗口就能看到最新数据

**验收标准:**
- [ ] 窗口打开时，每隔 30 秒自动刷新「今天」的数据
- [ ] 刷新不影响窗口滚动位置和当前视图
- [ ] 窗口关闭后再打开，数据为最新快照

### Story 4: 跨天自动归档

**作为** Lofi Radio 用户
**我想要** 每天结束时，当天的专注时长自动被保存下来
**以便** 不会丢失任何一天的数据

**验收标准:**
- [ ] 跨天时，前一天的专注总时长自动写入历史存储
- [ ] 今日数据在新的一天从 0 开始
- [ ] 同一天的数据不会重复归档（幂等）

## 功能需求

### 核心功能

**F1: 每日数据归档**

当前 `renderer.js` 的 `checkDateReset()` 检测到跨天时，在重置 focusTime 之前，先将昨日数据写入历史存储。

数据格式：
```json
{
  "2026-05-24": 120,
  "2026-05-23": 95,
  "2026-05-22": 180
}
```
key: `lofi-focus-history`

- 写入时机：`checkDateReset()` 检测到跨天时 + 每次 `saveToStorage()` 作为兜底
- 去重策略：同一天多次写入只保留最新值（按日期 key 覆盖即可）
- 过期清理：每次写入时检查记录数，删除 90 天前的记录

**F2: 历史窗口**

新建三个文件：
- `history.html` — 窗口布局
- `history.js` — 数据读取、柱状图渲染、视图切换、实时轮询
- `history.css` — 样式（复用主界面 glassmorphism 风格）

窗口规格：
- 尺寸：约 420×380（与 settings 窗口同级）
- 无边框（`frame: false`），可拖动（CSS `-webkit-app-region: drag`）
- 不可 resize、最大化、最小化

**F3: 柱状图**

- 纯 CSS 实现（div 元素 + 百分比高度），零依赖
- 每根柱子：顶部显示分钟数，底部显示日期
- 今天柱子使用主色调高亮（如 #7c5cfc），历史柱子使用暗色（如 rgba 半透明）
- Y 轴：自动根据数据最大值缩放，确保柱子高度合理（最高柱子约 90% 容器高度）
- 无数据的日期：显示空柱子（高度为 0 或最小高度占位）

**F4: 实时刷新**

- 窗口打开后，每 30 秒通过 IPC 从主进程获取当前 focusTime
- 或直接读取 `localStorage`（history 页面也 load 在 Electron 内，可直接访问）
- 仅更新「今天」那条柱子，不动其他柱子

### 排除范围

- ❌ 不记录会话明细（几点到几点）
- ❌ 不支持数据导出
- ❌ 不支持云端同步
- ❌ 不支持自定义日期范围（仅「周」「月」）
- ❌ 不做同比/环比/平均值等统计文字

## 技术约束

### 性能
- 历史数据最多 90 条，每条 < 20 bytes，总计 < 2KB
- 柱状图渲染时间 < 50ms
- 实时轮询间隔 30 秒，对主进程无感知影响

### 安全
- 数据全部存储于 `localStorage`，不涉及网络传输
- 无用户身份信息，纯匿名使用数据

### 技术栈
- 纯 vanilla HTML/CSS/JS（与现有项目保持一致）
- 无新增第三方依赖
- 窗口管理复用 `createSettingsWindow()` 模式（[main.js:431-462](main.js#L431-L462)）

### 兼容性
- 从旧版本升级的用户首次启动无历史数据，仅从升级当天开始积累
- 旧 `lofi-focus-time` key 保持不变，历史数据使用新 key `lofi-focus-history`

## 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| localStorage 数据被清理（浏览器清理工具/用户手动清除） | 低 | 低 | 数据丢失不影响核心播放功能；可考虑未来加 JSON 文件备份 |
| 跨时区导致日期判断错误 | 低 | 低 | 使用本地时间 `YYYY-MM-DD`，用户自行承担旅行时区变化 |
| 90 天数据累积影响 localStorage 性能 | 极低 | 极低 | 90 条记录 < 2KB，localStorage 通常有 5-10MB 容量 |
